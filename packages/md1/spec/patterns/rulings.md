# Patterns: web coverage rulings

Every page of the MD1 "Patterns" section, classified for `@paper/md1` under DESIGN_SYSTEMS ruling 7 (complete, exclusive, pinned). Categories: `component` (a new `Md1*` surface), `variant/prop` (of an existing component), `composition` (a documented composition example built from shipped components, or guidance a component page carries), `out of scope` (OS or browser feature; no surface).

## Sources

The 2018-12-25 archive index (`https://web.archive.org/web/20181225002255/https://material.io/archive/guidelines/`) lists 20 pattern pages; `app-shortcuts` is not among them. Each page below was fetched from the Wayback Machine over HTTPS with `curl`; the served capture timestamp is recorded per row. The archive's CDX index was queried for `app-shortcuts` on `material.io/guidelines`, `material.io/archive/guidelines`, `material.google.com` and `www.google.com/design/spec`: the only `patterns/app*` capture on any host is `app-structure.html` (a redirect), and no `material.io/guidelines` URL containing `shortcut` was ever captured. The 2018-02-23 snapshot of `patterns/app-shortcuts.html` returns a Wayback 404.

Vuetify 1.5.24 (`/home/john/sites/vuetify1`) was used only for the four component-style notes; it ships no pattern pages.

## Guidance that component notes must carry

The component researchers own these pages; the values and rules below were read on the pattern pages and must appear in the named component note, or be reconciled with it.

| Component note | Rule or value from the patterns section | Page | Confidence |
|---|---|---|---|
| text-fields | Helper text may appear before, during or after interaction; error text only after interaction; helper text may transform into error text; minimize form text | errors | high |
| text-fields | 16 dp vertical space between text fields and below the error text | errors | high |
| text-fields | Error text: Roboto Regular 12 sp (Caption). Hint and helper text: `#000000` at 38% (light), `#FFFFFF` at 50% (dark) | errors | high |
| text-fields | Error color: a contrasting color from the palette, "a warmer hue like red or orange"; legible against its background | errors | high |
| text-fields | Single-line with error text: tile height 64 dp; padding above input text 16 dp; below input text 8 dp; above and below error text 4 dp | errors | high |
| text-fields | Floating label with error text: tile height 80 dp; padding above label text 8 dp; above and below input text 8 dp; above and below error text 4 dp | errors | high |
| text-fields | Character counter: Roboto Regular 12 sp; counter fields have 16 dp additional bottom padding; consider hiding the counter until the user approaches the limit; with counter: height of the entire input area 88 dp, single-line label top padding 16 dp, input text top and bottom padding 8 dp, padding above counter 8 dp | errors | high |
| text-fields | Incompatible values: mark the field and add an error message below; summarize at the top of the form. ## Judgment calls for the lead

1. Persistent search: resolved in SPEC.md as the `Md1SearchBar` component sharing one `Combobox` core with the `Search` part of `Md1Toolbar`; the one-`Md1Search`-with-two-variants alternative is rejected. SPEC.md open question 5 asks the lead to confirm. The page gives no metrics either way.
2. Swipe to refresh: composition example (as ruled); SPEC.md rejects the `Md1SwipeRefresh` wrapper. No v0 gesture primitive exists to compose from.
3. The spec is silent on the scrim, the mini width and the mobile breakpoint; whichever values ship must be declared in `SPEC.md` as deviations with the Vuetify 1.5 numbers as the precedent.
4. The generic note template names `spec/components/<slug>.md`; this assignment named `spec/patterns/`, so the four component-style notes live under `spec/patterns/`. No per-page notes were written for the 17 non-component pattern pages; their content is in the tables above.
